## [Unreleased] — 2026-11-18

**Type:** Feature

### 📝 Summary

The random requests generated by `bruno-collection` now use realistic values (uuid,
16-digit KTP, ISO date, e-mail, `+62` phone, names, places, plates, coordinates) picked
from the declared example and the field name, through a `fake` library kept in the
collection-level script. Generated uuids start with `bruno` so a Bruno call can be told
apart from a real request in the service's tables. A small Python 3.9 fix to the
`template-sync` stamp is included.

### 📋 Changes Made

**Files Modified**

- `CLAUDE/skills/bruno-collection/scripts/bruno_fake.py` — new `fake` JS library; `uuid()`
  starts with `bruno`
- `CLAUDE/skills/bruno-collection/scripts/bruno_values.py`, `bruno_collection.py` — pick the
  fake call from the example and the field name
- `CLAUDE/skills/bruno-collection/SKILL.md` — documents the realistic-values and uuid rules
- `CLAUDE/skills/template-sync/scripts/template_sync.py` — `write_bytes` instead of
  `write_text(newline="")` (needs 3.10; the helper runs on 3.9)
- `tests/test_bruno_fake.py`, `tests/test_bruno_render.py` — cover the library and the picking rules

### ⚠️ Behaviour Changes

- A strict `UUID`-typed field keeps a hex uuid (`bruno` is not hex and would be rejected).
- Realistic values can match a real person: send them only to a test service.

### 🧪 Testing

`uv run pytest`, `ruff check`, `ruff format --check` and `mypy` pass.
